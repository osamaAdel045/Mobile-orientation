    ### Storage Tier Comparison

    | Feature | Hive | Drift (SQLite) | Isar | SharedPrefs | Secure Storage |
    |---|---|---|---|---|---|
    | Database type | NoSQL KV | Relational (SQL) | NoSQL document | KV | Encrypted KV |

    ### Hive Deep Dive: TypeAdapter Code Generation

    Hive stores Dart objects in binary boxes via `@HiveType` annotated adapters generated by `hive_generator`. Each `@HiveField(index)` maps to a column position — **never change the index of an existing field after shipping** or stored data deserializes incorrectly. Add new fields with the next unused index.

    ```dart
    @HiveType(typeId: 0)
    class User extends HiveObject {
      @HiveField(0) final String id;
      @HiveField(1) final String name;
      @HiveField(2) final DateTime createdAt;
      User({required this.id, required this.name, required this.createdAt});
    }

    // Setup
    await Hive.initFlutter();
    Hive.registerAdapter(UserAdapter());
    await Hive.openBox<User>('users');
    ```

    Boxes can be **lazy** (loaded on first access) or **encrypted** (AES-256 via `EncryptedBox`). Use one box per entity type for clean lifecycle management. Batch writes with `box.putAll()` for performance.

    <Callout title="Hive Field Indexes Are Immutable">
      After shipping, never reorder `@HiveField` indexes and never reuse a deleted index. Hive serializes by index position, not field name. Version your box schemas and always test with stored data before each release. This is Hive's biggest production footgun.
    </Callout>

    ### Drift (SQLite): Schema, Joins, and Migrations

    Drift uses compile-time validated Dart SQL queries. Annotate tables with `@DataClassName` and write queries with full IntelliSense.

    ```dart
    @DataClassName('Product')
    class Products extends Table {
      IntColumn get id => integer().autoIncrement()();
      TextColumn get name => text().withLength(min: 1, max: 255)();
      RealColumn get price => real()();
      IntColumn get categoryId => integer().references(Categories, #id)();
    }

    // Join query
    Future<List<ProductWithCategory>> productsWithCategories() {
      return (select(products).join([
        innerJoin(categories, categories.id.equalsExp(products.categoryId)),
      ])).map((row) => ProductWithCategory(
        product: row.read(products),
        category: row.read(categories),
      )).get();
    }

    // Migration
    @override
    MigrationStrategy get migration => MigrationStrategy(
      onUpgrade: (migrator, from, to) async {
        if (from == 1) await migrator.addColumn(products, products.createdAt);
      },
    );
    ```

    ### Isar for Complex NoSQL Queries

    Isar provides memory-mapped NoSQL storage with filtering, sorting, indexed `where` clauses, and lazy-loading relations (`IsarLinks`) — combining Hive's performance with SQL-like query power, all in pure Dart.

    ```dart
    @collection
    class Post {
      Id id = Isar.autoIncrement;
      late String title;
      @Index() late DateTime createdAt;
      final comments = IsarLinks<Comment>();
    }

    final posts = await isar.posts.where()
      .createdAtBetween(oneWeekAgo, DateTime.now())
      .sortByCreatedAtDesc().limit(20).findAll();
    ```

    ### Caching Layer Architecture

    Three-tier cache: in-memory `Map` (session-scoped, instant) -> local DB (persists across restarts) -> remote API. The repository checks memory first, then local DB, then network — writing results back down the chain.

    ```dart
    class CachedRepository<T> {
      T? _memory;
      final Box<T> _local;

      Future<T> get(String key, Future<T> Function() remoteFetch) async {
        if (_memory != null) return _memory!;
        final cached = _local.get(key);
        if (cached != null) { _memory = cached; return cached; }
        final remote = await remoteFetch();
        _memory = remote;
        await _local.put(key, remote);
        return remote;
      }
    }
    ```

    <Callout title="Testing with In-Memory Databases">
      Drift supports `NativeDatabase.memory()`, Hive uses `Hive.openBox('test', path: tempDir)`, Isar offers `Isar.open(directory: ':memory:')`. Always inject the database instance via DI so tests can swap production file-backed DBs for in-memory ones — no cleanup, no flaky state between test runs.
    </Callout>

    ### flutter_secure_storage: Platform Internals

    On iOS, values live in the Keychain (encrypted at rest with the device passcode). On Android, it uses `EncryptedSharedPreferences` (AES-256/GCM) when available, falling back to `AndroidKeyStore`. Each read/write requires a native channel hop (~10-50ms) — never store large or frequently-accessed data here. Only tokens, API keys, and biometric credentials.

    ### Data Synchronization Strategy

    When the app comes online: replay queued local writes first (last-write-wins conflict resolution), then refresh stale cache entries from the API. Use a `SyncService` that observes connectivity changes via `connectivity_plus` and triggers a background pull for each modified entity.

    ### Comparison: React Native / Native Storage

    React Native's `AsyncStorage` is an unencrypted KV store with a 6 MB Android limit — similar to SharedPreferences but larger. For SQL, `react-native-sqlite-storage` mirrors Drift but lacks compile-time type safety. iOS native `CoreData` is a full ORM with faulting and undo management — heavier than Drift but better for complex object graphs. Android `Room` is architecturally closest to Drift: annotation-based schema, compile-time query verification, and `AutoMigration`.
