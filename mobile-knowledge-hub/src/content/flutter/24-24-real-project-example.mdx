    ### Authentication Flow

    Auth state is a sealed union managed by a Riverpod `NotifierProvider`. GoRouter redirects guards via `ref.watch(authProvider)`. The flow: Google/Apple Sign-In -> Firebase Auth -> backend JWT -> stored in `flutter_secure_storage`.

    ```dart
    @freezed
    sealed class AuthState with _$AuthState {
      const factory AuthState.initial() = _Initial;
      const factory AuthState.loading() = _Loading;
      const factory AuthState.authenticated(User user) = _Authenticated;
      const factory AuthState.unauthenticated() = _Unauthenticated;
      const factory AuthState.error(String message) = _Error;
    }

    @riverpod
    class AuthNotifier extends _$AuthNotifier {
      @override
      AuthState build() => const AuthState.initial();

      Future<void> signInWithGoogle() async {
        state = const AuthState.loading();
        try {
          final result = await _googleSignIn.signIn();
          final credential = GoogleAuthProvider.credential(accessToken: result!.authentication.accessToken);
          final authResult = await _firebaseAuth.signInWithCredential(credential);
          state = AuthState.authenticated(_mapFirebaseUser(authResult.user!));
        } on FirebaseAuthException catch (e) {
          state = AuthState.error(e.message ?? 'Sign in failed');
        }
      }
    }
    ```

    ### Data Flow: Cache-First Feed

    The feed provider fetches through a repository implementing a cache-first strategy: return Drift-cached data immediately, fetch fresh data from the Dio API in the background, then update the cache.

    ```dart
    @riverpod
    class FeedProvider extends _$FeedProvider {
      @override
      Future<List<Article>> build() async {
        return ref.watch(articleRepositoryProvider).getFeed();
      }
    }

    class ArticleRepositoryImpl implements ArticleRepository {
      final ArticleRemoteDataSource _remote;
      final ArticleLocalDataSource _local;

      @override
      Future<List<Article>> getFeed() async {
        final cached = await _local.getCachedFeed();
        if (cached != null) return cached; // Instant display
        final dtos = await _remote.fetchFeed(); // API call
        await _local.cacheFeed(dtos);            // Cache for offline
        return dtos.map((dto) => dto.toEntity()).toList();
      }
    }

    class ArticleRemoteDataSource {
      final Dio _dio;
      Future<List<ArticleDTO>> fetchFeed() async {
        final response = await _dio.get('/api/v1/feed');
        return (response.data as List).map((j) => ArticleDTO.fromJson(j)).toList();
      }
    }
    ```

    <Callout title="Offline Strategy: Two-Tier Cache">
        Drift (SQLite) stores structured data with full query capability for offline browsing. Hive stores serialized API response blobs for fast startup. On connectivity loss, reads come from Drift and writes queue to a local mutation log. A `connectivity_plus` listener triggers sync when the network returns — the user can browse, bookmark, and compose content offline with transparent background sync.
    </Callout>

    ### Push Notifications and Deep Linking

    FCM delivers tokens via `onTokenRefresh` — the token is stored on the backend for targeted notifications. `flutter_local_notifications` displays them with platform-appropriate channels/categories. Tapping a notification reads the `article_id` from the payload and deep-links via GoRouter.

    ```dart
    class NotificationService {
      final FirebaseMessaging _fcm = FirebaseMessaging.instance;

      Future<void> initialize() async {
        await _fcm.requestPermission();
        final token = await _fcm.getToken();
        await _sendTokenToBackend(token!);
        FirebaseMessaging.onMessageOpenedApp.listen(_handleDeepLink);
        FirebaseMessaging.onMessage.listen((msg) {
          _localNotifications.show(msg.hashCode, msg.notification?.title,
            msg.notification?.body, const NotificationDetails(
              android: AndroidNotificationDetails('feed_channel', 'Feed'),
              iOS: DarwinNotificationDetails()));
        });
      }

      void _handleDeepLink(RemoteMessage msg) {
        final id = msg.data['article_id'];
        if (id != null) GoRouter.of(navigatorKey.currentContext!).go('/article/$id');
      }
    }
    ```

    ### CI/CD and Testing

    **CI/CD:** GitHub Actions runs `flutter analyze`, unit tests, and widget tests on every PR. Merges to main trigger integration tests on Firebase Test Lab, then Codemagic builds AAB + IPA with Sentry source map uploads and submits to App Store Connect / Google Play.

    **Testing strategy:** Domain logic tested with `mocktail` (no code generation, pure Dart). Repository tests use in-memory fake data sources instead of mocks for full data-flow verification. Widget tests override providers with `ProviderScope.overrides`. Golden tests with `golden_toolkit` capture visual snapshots on light/dark themes. Targets: 85% coverage on domain + data layers, 65% on presentation, 3 integration smoke tests per critical journey.

    ### Production Considerations

    Sentry captures errors via `FlutterError.onError` with device context. Firebase Analytics tracks screen views with `FirebaseAnalyticsObserver` on GoRouter. Release builds use `--split-debug-info` and `--obfuscate`, reducing binary ~15%. The app demonstrates both Flutter's strengths (full code sharing, hot reload for UI iteration, Riverpod compile-time safety, Drift type-safe SQLite) and its pain points (platform channel debugging for FCM on certain Android OEMs, 8.2 MB release binary vs ~2 MB native, Dart isolate concurrency learning curve).
