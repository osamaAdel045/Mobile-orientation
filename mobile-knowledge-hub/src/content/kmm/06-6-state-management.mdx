      ### Two-Layer State Management

      KMP divides state management into two distinct layers. The **shared layer**
      (commonMain) models business state using Kotlin `StateFlow` and sealed classes.
      The **UI layer** (platform-specific) maps that state to native widgets. This
      separation ensures the shared module has zero UI dependencies while each platform
      can render state in its idiomatic way.

      ```kotlin
      // commonMain — shared UI state sealed class
      sealed class AuthState {
          data object Idle : AuthState()
          data object Loading : AuthState()
          data class Authenticated(val user: User, val token: String) : AuthState()
          data class Error(val message: String) : AuthState()
      }

      // commonMain — shared ViewModel
      class AuthViewModel(
          private val authRepo: AuthRepository,
          private val scope: CoroutineScope
      ) {
          private val _state = MutableStateFlow<AuthState>(AuthState.Idle)
          val state: StateFlow<AuthState> = _state.asStateFlow()

          fun login(email: String, password: String) {
              _state.value = AuthState.Loading
              scope.launch {
                  try {
                      val user = authRepo.login(email, password)
                      _state.value = AuthState.Authenticated(user, user.token)
                  } catch (e: Exception) {
                      _state.value = AuthState.Error(e.message ?: "Unknown error")
                  }
              }
          }
      }
      ```

      ### Android Consumption — Jetpack Compose

      Android observes `StateFlow` with Compose's `collectAsStateWithLifecycle()`,
      which respects the Android lifecycle — collecting stops when the composable
      leaves the composition and restarts when it re-enters.

      ```kotlin
      // androidApp — Compose consumption
      @Composable
      fun AuthScreen(viewModel: AuthViewModel) {
          val state by viewModel.state.collectAsStateWithLifecycle()
          when (val s = state) {
              is AuthState.Idle -> LoginForm(onLogin = viewModel::login)
              is AuthState.Loading -> CircularProgressIndicator()
              is AuthState.Authenticated -> Dashboard(s.user)
              is AuthState.Error -> ErrorBanner(s.message)
          }
      }
      ```

      ### iOS Consumption — SwiftUI with SKIE

      On iOS, SKIE converts `StateFlow` into a `Swift AsyncSequence`. SwiftUI's `task`
      modifier iterates over the async sequence and updates the view when state changes.

      ```swift
      // iosApp — SwiftUI with SKIE AsyncSequence
      struct AuthScreen: View {
          let viewModel: AuthViewModel
          @State private var state: AuthState = .idle

          var body: some View {
              Group {
                  switch state {
                  case .idle:        LoginForm { email, pass in viewModel.login(email, pass) }
                  case .loading:     ProgressView()
                  case .authenticated(let user, _): DashboardView(user: user)
                  case .error(let msg): ErrorView(message: msg)
                  }
              }
              .task {
                  for await s in viewModel.state.asyncSequence {
                      state = s
                  }
              }
          }
      }
      ```

      <Callout title="ViewModel Lifecycle in Common Code">
        KMP ViewModels cannot use Android's `ViewModel` class (JVM-only). Instead,
        use manual `CoroutineScope` management or the `kmp-viewmodel` library
        (from IceRock) which provides a KMP-compatible ViewModel base class with
        automatic scope cancellation. On iOS, the ViewModel is created in Swift
        and its scope ties to the SwiftUI view lifecycle via `@StateObject`.
      </Callout>

      ### Comparison: KMP State vs Flutter/Redux

      | Aspect | KMP (StateFlow) | Flutter (Riverpod) | Redux |
      |--------|-----------------|--------------------|-------|
      | State Type | StateFlow | StateNotifier | Store |
      | Immutability | copy() with data class | copyWith() | Reducer pure fn |
      | Side Effects | suspend function | AsyncNotifier | Middleware |
      | Platform Bridge | SKIE AsyncSequence | Dart (direct) | JS Bridge |
      | Lifecycle | CoroutineScope | Widget lifecycle | Subscriptions |

      ### Pitfall: Shared Mutable State

      ```kotlin
      // WRONG — mutable state exposed directly to both platforms
      class WrongViewModel {
          var count = 0
      }

      // RIGHT — immutable state via StateFlow
      class RightViewModel {
          private val _state = MutableStateFlow(0)
          val state: StateFlow<Int> = _state.asStateFlow()
      }
      ```

      ### KMP Insight

      State management in KMP treats the shared module as a **state producer** and
      each platform as a **state consumer**. The boundary is the `StateFlow` type
      — which SKIE translates into Swift's `AsyncSequence` and Android observes
      natively with `Flow.collect()`. No serialization, no bridge overhead.

      <Callout title="The RN State Lesson">
        RN's CLAUDE.md mandated a discriminated union with four states: Loading,
        Loaded (with typed data), Error (with message), and Empty. The audit
        found only 8/16 stores used it correctly. 5 stores used ad-hoc flags
        (isLoading, error string, etc.). Auth and checkout — the two stores
        CLAUDE.md named explicitly — did not use the union at all. In KMP, the
        ScreenState sealed interface is **the only allowed screen-state type**
        in ViewModels. detekt flags any ViewModel that exposes a non-sealed
        state type.
      </Callout>

      ### The Canonical ScreenState

      ```kotlin
      // shared/src/commonMain/.../core/errors/ScreenState.kt
      // The ONLY screen-state type allowed in ViewModels.
      // detekt rule: ViewModelMustUseScreenState — flags any ViewModel
      // whose primary state property is not StateFlow<ScreenState<*>>

      sealed interface ScreenState<out T> {
          data object Loading : ScreenState<Nothing>
          data class Loaded<T>(val data: T) : ScreenState<T>
          data class Error(val message: String) : ScreenState<Nothing>
          data object Empty : ScreenState<Nothing>
      }
      ```

      ### The AppResult Type (Neverthrow Equivalent)

      ```kotlin
      // shared/src/commonMain/.../core/errors/AppResult.kt
      // Every Repository method returns AppResult<T> — NEVER throws.
      // ViewModels use when(result) { is AppResult.Success → … is AppResult.Failure → … }
      // runCatching { } is BANNED in ViewModels (detekt: NoRunCatchingInViewModel)

      sealed class AppResult<out T> {
          data class Success<T>(val data: T) : AppResult<T>()
          data class Failure(val error: AppError) : AppResult<Nothing>()

          val isSuccess: Boolean get() = this is Success
          val isFailure: Boolean get() = this is Failure

          fun <R> map(transform: (T) -> R): AppResult<R> = when (this) {
              is Success -> Success(transform(data))
              is Failure -> this
          }

          fun getOrNull(): T? = when (this) {
              is Success -> data
              is Failure -> null
          }
      }

      sealed class AppError(
          open val message: String,
          open val code: String? = null,
      ) {
          data class NetworkError(override val message: String) : AppError(message)
          data class ServerError(override val message: String, override val code: String? = null) : AppError(message, code)
          data class Unauthorized(override val message: String = "Session expired") : AppError(message)
          data class ValidationError(override val message: String, val errors: Map<String, List<String>>) : AppError(message)
          data class Unknown(override val message: String = "Something went wrong") : AppError(message)
      }
      ```

      ### ViewModel Template — The Only Allowed Pattern

      ```kotlin
      // composeApp/.../features/<feature>/presentation/<Feature>ViewModel.kt
      // THIS IS THE CANONICAL VIEWMODEL TEMPLATE.
      // Scaffold generates this exact structure. Deviations fail detekt.

      class FeatureViewModel(
          private val repository: FeatureRepository,
      ) : ViewModel() {

          private val _screenState = MutableStateFlow<ScreenState<FeatureData>>(ScreenState.Loading)
          val screenState: StateFlow<ScreenState<FeatureData>> = _screenState.asStateFlow()

          init {
              loadData()
          }

          fun loadData() {
              viewModelScope.launch {
                  _screenState.value = ScreenState.Loading
                  repository.getData().let { result ->
                      when (result) {
                          is AppResult.Success -> {
                              _screenState.value = if (result.data.isEmpty())
                                  ScreenState.Empty
                              else
                                  ScreenState.Loaded(result.data)
                          }
                          is AppResult.Failure -> {
                              _screenState.value = ScreenState.Error(result.error.message)
                          }
                      }
                  }
              }
          }

          fun refresh() {
              viewModelScope.launch {
                  // Keep last-good state visible during refresh
                  repository.refreshData().let { result ->
                      when (result) {
                          is AppResult.Success -> {
                              _screenState.value = if (result.data.isEmpty())
                                  ScreenState.Empty
                              else
                                  ScreenState.Loaded(result.data)
                          }
                          is AppResult.Failure -> { /* Keep last-good data on transient error */ }
                      }
                  }
              }
          }
      }
      ```

      ### With Persistence — The Rehydration Pattern

      ```kotlin
      // For features with cached data (cart, orders, restaurants, earnings):
      // ViewModel rehydrates from SQLDelight BEFORE the first network call.

      class CartViewModel(
          private val cartRepo: CartRepository,
      ) : ViewModel() {

          private val _screenState = MutableStateFlow<ScreenState<Cart>>(ScreenState.Loading)
          val screenState: StateFlow<ScreenState<Cart>> = _screenState.asStateFlow()

          init {
              viewModelScope.launch {
                  // 1. REHYDRATE — instant, survives app restart
                  cartRepo.getCachedCart()?.let { cart ->
                      _screenState.value = if (cart.items.isEmpty())
                          ScreenState.Empty
                      else
                          ScreenState.Loaded(cart)
                  }
                  // 2. REFRESH — network updates DB + state
                  cartRepo.refreshCart()
                      .onSuccess { cart ->
                          _screenState.value = if (cart.items.isEmpty())
                              ScreenState.Empty
                          else
                              ScreenState.Loaded(cart)
                      }
                      .onFailure { /* Keep cached data visible on transient error */ }
              }
          }
      }
      ```

      ### Screen Consumption — The Only Allowed Pattern

      ```kotlin
      // Screen renders the ScreenState. That's it. No business logic.
      @Composable
      fun FeatureScreen(
          viewModel: FeatureViewModel = koinViewModel(),
          onNavigate: (id: String) -> Unit,
      ) {
          val screenState by viewModel.screenState.collectAsStateWithLifecycle()

          when (val state = screenState) {
              is ScreenState.Loading -> LoadingSkeleton()
              is ScreenState.Loaded -> FeatureContent(
                  data = state.data,
                  onRefresh = viewModel::refresh,
                  onItemClick = onNavigate,
              )
              is ScreenState.Empty -> EmptyState(
                  message = stringResource(R.string.feature_empty),
              )
              is ScreenState.Error -> ErrorState(
                  message = state.message,
                  onRetry = viewModel::loadData,
              )
          }
      }
      ```

      <Callout title="Why Sealed Interface, Not Enum">
        Kotlin sealed interfaces allow `ScreenState.Loaded<T>` to carry typed
        data while `ScreenState.Loading`/`Error`/`Empty` carry no data. This is
        structurally identical to TypeScript's discriminated union but
        compile-time exhaustive — `when` without all 4 branches is a compiler
        error. RN's TypeScript discriminated union is runtime-only; nothing
        enforced the `'empty'` branch in `restaurant.store.ts` and it was
        silently missing.
      </Callout>
