### Project Overview

A field-service inspection app for a mid-size enterprise. Technicians use iOS and Android devices to receive work orders, complete inspection checklists offline, sync when connectivity resumes, and receive push notifications for urgent assignments. Backend: Azure Functions + SQL Server with a REST API.

### Architecture

**Shell + MVVM layout:**
```
┌──────────────────────────────────┐
│          Shell App               │
│  TabBar(WOrders, Dashboard)      │
│  FlyoutItem(Settings, Logout)    │
│         │                        │
│  ┌──────▼─────────────────┐      │
│  │  MVVM Layer            │      │
│  │  VM ←→ Service ←→ API  │      │
│  │     ↕         ↕        │      │
│  │  SQLite   SecureStorage│      │
│  └────────────────────────┘      │
└──────────────────────────────────┘
```

**Data flow**: `ViewModel` calls `ISyncService.FetchWorkOrdersAsync()` -> service checks `Connectivity.Current.NetworkAccess` -> if online, calls `IWorkOrderApi.GetPendingAsync()` via Refit -> deserializes JSON -> stores in SQLite via `IRepository<T>` -> publishes `WorkOrdersLoadedMessage` via `WeakReferenceMessenger` -> ViewModel updates `ObservableCollection<WorkOrder>`. If offline, loads from SQLite directly and queues a sync job.

**Offline sync with SQLite retry queue:**
```csharp
public class SyncService : ISyncService
{
    private readonly IRepository<SyncQueueItem> _queue;
    public async Task SyncPendingAsync()
    {
        var pending = await _queue.GetManyAsync(q => q.Status == SyncStatus.Pending);
        foreach (var item in pending.OrderBy(i => i.CreatedAt))
        {
            try
            {
                await _api.PostInspectionAsync(item.Payload);
                item.Status = SyncStatus.Completed;
            }
            catch (HttpRequestException)
            {
                item.Status = SyncStatus.Failed;
                item.RetryCount++;
            }
            await _queue.UpdateAsync(item);
        }
    }
}
```

<Callout variant="default" title="Offline-First Pattern">
All data reads go through SQLite first. The API refreshes in the background. This keeps the UI responsive regardless of connectivity. Conflicts use "last-write-wins" with `UpdatedAt` timestamps.
</Callout>

**Secure credential storage with MSAL:**
```csharp
public async Task<string> GetAccessTokenAsync()
{
    var cached = await SecureStorage.GetAsync("access_token");
    if (!string.IsNullOrEmpty(cached)) return cached;

    var authResult = await _pca.AcquireTokenInteractive(scopes)
        .WithParentActivityOrWindow(Platform.CurrentActivity)
        .ExecuteAsync();
    await SecureStorage.SetAsync("access_token", authResult.AccessToken);
    return authResult.AccessToken;
}
```

### CI/CD Pipeline

**GitHub Actions** builds, tests (via `dotnet test` with `Microsoft.Maui.Testing`), and publishes to App Center / TestFlight (iOS) and Google Play (Android) on each tag push. A macOS runner handles iOS; a Windows runner handles Android. The pipeline runs `maui-check` to validate the environment before building.

<Callout variant="info" title="Production Checklist">
Before shipping: verify compiled bindings on every page (set `x:DataType`), prune unused NuGet packages, enable linker (`<MtouchLink>Full</MtouchLink>` on iOS, `<AndroidLinkMode>SdkOnly</AndroidLinkMode>` on Android), and test all offline flows with airplane mode enabled.
</Callout>
